# Product Backlog — SmartDesk ITSM API

У цьому документі міститься перелік User Stories, критерії їх завершеності (Acceptance Criteria) та пріоритезований Backlog задач системи SmartDesk.

---

## 1. User Stories & Acceptance Criteria

### US-01: Створення інциденту та отримання AI-підказок

- **Формулювання:** Як **співробітник компанії**, я хочу **реєструвати новий тікет та одразу бачити схожі закриті інциденти**, щоб **швидко вирішити проблему самостійно без очікування інженера**.
- **Acceptance Criteria (AC):**
  1. Користувач заповнює заголовок (min 5 слів), опис (min 10 слів), категорію та статичний пріоритет (1–4).
  2. Система автоматично генерує 384-вимірний вектор (Embedding) за допомогою моделі `all-MiniLM-L6-v2`.
  3. Система розраховує Cosine Similarity з усіма закритими тікетами тієї ж категорії.
  4. Повертається максимум 3 найсхожіших рішення з коефіцієнтом збігу $\ge 0.35$.

### US-02: Смарт-черга інженерів (Dynamic Urgency)

- **Формулювання:** Як **інженер техпідтримки**, я хочу **бачити список задач, відсортований за динамічним індексом Urgency**, щоб **своєчасно реагувати на критичні проблеми та не порушувати SLA**.
- **Acceptance Criteria (AC):**
  1. Запит `GET /tickets/queue` повертає лише відкриті інциденти (`status != 'Closed'`).
  2. Штраф за час розраховується поліморфно через патерн Strategy (Hardware — лінійний, General — квадратичний, Security — кубічний).
  3. Тікети у списку відсортовані за спаданням балу `dynamic_urgency`.

### US-03: Редагування тікета та re-indexing

- **Формулювання:** Як **користувач**, я хочу **редагувати опис та заголовок створеного тікета**, щоб **уточнити деталі проблеми без створення дублікатів**.
- **Acceptance Criteria (AC):**
  1. Запит `PUT /tickets/{id}` дозволяє змінити заголовок, опис, категорію або пріоритет.
  2. При зміні тексту заголовка чи опису система автоматично перераховує та оновлює збережений вектор у базі даних.

### US-04: Зміна статусу та поповнення бази знань

- **Формулювання:** Як **інженер техпідтримки**, я хочу **змінювати статус заявки (Open -> In Progress -> Closed)**, щоб **фіксувати прогрес та зберігати нові рішення в базі знань**.
- **Acceptance Criteria (AC):**
  1. Запит `PATCH /tickets/{id}/status` змінює стан тікета.
  2. Перехід у статус `Closed` робить цей тікет доступним для семантичного пошуку іншими користувачами.

### US-05: Видалення застарілих тікетів

- **Формулювання:** Як **адміністратор системи**, я хочу **видаляти помилкові або тестові тікети**, щоб **підтримувати базу даних у чистому стані**.
- **Acceptance Criteria (AC):**
  1. Запит `DELETE /tickets/{id}` видаляє запис із бази SQLite.
  2. Повертається статус HTTP 204 No Content.
